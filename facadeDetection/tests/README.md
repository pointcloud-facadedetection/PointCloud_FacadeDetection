# 测试说明

测试按软件功能分目录。想看某块功能有没有测、测了什么，直接进对应目录：

| 目录 | 管什么 |
|---|---|
| `project/` | 项目新建、打开、删除；后台加载与加载窗口；进度提示；项目资源校验 |
| `pointcloud/` | 点云读取与磁盘缓存、代理点云构建、去噪、站点数据复用与释放、多站配准 |
| `detection/` | 立面检测算法、检测用法线缓存、点云变化后旧检测结果的失效判断 |
| `quality/` | 质量评估：全局平面、靠尺平整度、评估流程控制、评估后台任务、热力图导出 |
| `review/` | 检测复核页：呈现方式、测距与放靠尺、调整边界 |
| `viewport/` | 三维视图：选中立面聚焦、触控缩放、页面隐藏时停止渲染 |
| `report/` | 报告预览；报告读取的数据结构（键名冻结，改了要先和报告侧对齐） |
| `architecture/` | 代码分层约定：界面层不碰服务私有字段、服务层不弹窗、对外接口不回退 |
| `support/` | 测试公用的假服务、信号记录器等，不放测试用例 |

## 怎么跑

在 `facadeDetection/` 目录下（需要 pytest 和 pytest-qt）：

```bash
pytest tests               # 日常：全部用例，跳过 slow，约 1 分钟
pytest tests/quality       # 只跑某一块
pytest tests --slow        # 连 slow 一起跑，约 3 分半
```

`slow` 是为验证某次优化而把数据放大到几十万、上百万点的用例（检测结果与旧实现逐点一致、
代理点云构建提速）。平时跳过；改了检测算法或代理点云构建时加 `--slow` 跑一遍。

## 新加测试放哪

- 按"测的是哪块功能"放进对应目录；文件名写清测的对象，例如 `test_ruler_quality.py`。
- 文件名在整个 `tests/` 里不能重名：各目录没有 `__init__.py`，pytest 按文件名导入。
- 单个要跑十几秒以上、为验证优化而放大数据量的用例，加 `@pytest.mark.slow`。
- 公用替身放 `support/`，用 `from support.fakes import ...` 导入。
- 不创建真实项目目录或数据库：涉及 Storage 的代码在测试里打桩。
